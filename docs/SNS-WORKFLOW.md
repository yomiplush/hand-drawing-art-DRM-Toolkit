# SNS 投稿・作品配布の実践ワークフローガイド (`SNS-WORKFLOW.md`)

このガイドは、**X (Twitter)・Instagram・Bluesky・Misskey・pixiv などの SNS にイラストを投稿する絵師さん向け**に、Certified Handmade の暗号証明を無理なく活用するための実践レシピをまとめたものです。

---

## 1. なぜ SNS に投稿すると「ピクセル一致」が外れるのか？

Certified Handmade の暗号証明（`CAR-v1` `SHA-256`）は、**1ピクセルでも変化すると検知できる厳密なハッシュ**です。  
一方で、ほとんどの SNS は画像をアップロードすると自動で **JPEG / WebP への再圧縮やリサイズ** を行います。

- **元の署名済み PNG（原本）**: 署名・ピクセルハッシュともに **完全一致（Matched）** します。
- **SNS から保存した再圧縮画像**: 画質劣化によりピクセル値が変わるため、暗号的なピクセルハッシュは **不一致（Mismatched）** になります（ただし、QR コード自体が読めれば「誰が・どの宣言で署名したか」の署名自体は検証できます）。

これはバグではなく、暗号学的改ざん検知の正しい挙動です。そのため、**「SNS 投稿用」と「原本 PNG の配布先」を分ける運用**が最も確実です。

---

## 2. おすすめの運用レシピ（3ステップ）

### ステップ 1: 署名済み PNG（原本）を作成する
1. `/create` で作業ファイル（`.psd`, `.clip`, `.procreate`, `.kra` 等）から署名済み PNG を書き出します。
2. 書き出した **署名済み PNG（原本）** は、画質劣化しない場所（ご自身の PC / SSD / クラウドストレージ等）にそのまま保管します。
3. 必要に応じて、証明データ（`.chproof.json`）や作業ファイルの証跡（`.chmevidence`）も一緒に保管しておきます。

### ステップ 2: SNS には「QR が読める状態」で投稿する
- **Protocol v2 / v3（画像内マスク配置）** または **Protocol v1（外枠配置）** で書き出した PNG をそのまま SNS に投稿します。
- SNS 側で再圧縮されても、QR コードが潰れずに読み取れれば、閲覧者はスマホカメラや `/verify` から **作者の Ed25519 署名・作品メタデータ・利用ポリシー（AI 学習可否など）** を確認できます。
- **コツ**: 画像が極端に縮小される SNS では、QR サイズを少し大きめ（または外枠配置）にすると読み取りやすくなります。

### ステップ 3: 厳密な原本検証が必要な相手には「再圧縮されない場所」で渡す
依頼主（クライアント）・ファン支援サイト（FANBOX / Fantia / BOOTH 等）・ポートフォリオサイトなど、**完全なピクセル一致（Matched）を証明したい場合**は、SNS 経由ではなく以下のように原本 PNG を配布します：

| 配布方法 | ピクセル一致 (`SHA-256`) | おすすめ用途 |
| --- | --- | --- |
| **BOOTH / FANBOX / Fantia / Google Drive 等のファイル配布（PNG そのまま or ZIP）** | **完全一致（Matched）** | コミッション納品、支援者向け高解像度版、原本保管 |
| **X / Instagram / Bluesky 等の通常投稿** | 不一致になりやすい（再圧縮のため） | 告知・閲覧用、QR からの作者署名・ポリシー確認 |

## 3. `dHash64` / `pHash64`（視覚的類似度チェック）の位置づけ

`/verify` 画面には、SNS 再圧縮画像と原本の視覚的な近さを確認するための **`dHash64` / `DCT pHash64` 視覚的類似度ヘルパー** が用意されています。

- **できること**: SNS から保存した JPEG/WebP 画像が、原本 PNG と「見た目としてほぼ同じ画像か」を手元で素早く確認する補助になります。
- **できないこと（重要）**: `dHash64` / `pHash64` は **暗号学的証明ではありません（`isCryptographic: false`）**。法的・暗号学的な同一性証明として `CAR-v1` `SHA-256` の代わりにはなりません。
- **使い分け**:
  - 普段の確認・SNS 上の参照チェック → QR 署名検証 ＋ `dHash64` / `pHash64`（参考情報）
  - 納品物・トラブル時の厳密な証明 → 再圧縮されていない **原本 PNG** での `SHA-256` 一致検証 ＋ 必要に応じた `.chmevidence`（作業ファイル照合）

## 4. 絵師さん向けクイックチェックリスト

- [ ] 署名済み PNG（原本）を SNS に上げる前に、元のまま手元に保存した
- [ ] バックアップ鍵（`.chkey.json`）を `/keys` の「バックアップを検証のみ（Verify Backup Only）」で復号テスト済み
- [ ] クライアント納品や原本配布は、再圧縮されない形式（PNG 原本 / ZIP）で渡している
- [ ] 自分の公開鍵フィンガープリント（64桁の SHA-256）をプロフィールや `/exchange` で共有している
